## 1. 术语表说明

### 1.1 目的与范围

本术语表旨在为 MyOpenClaw 项目的所有参与者（开发者、最终用户、文档编写者）提供统一、准确的术语定义参考。术语表覆盖 MyOpenClaw 的核心概念、架构设计、消息协议、记忆存储、AI 模型与安全机制等各个领域的专业术语。

### 1.2 术语条目结构

每个术语条目包含以下字段：

| 字段 | 说明 |
|------|------|
| 术语名称 | 术语的中文名称和英文名称 |
| 缩写 | 术语的常用缩写（如有） |
| 定义说明 | 术语的准确定义和详细解释 |
| 所属模块/领域 | 该术语所属的系统模块或知识领域 |
| 相关术语 | 与该术语有关联的其他术语，便于交叉参考 |

### 1.3 使用约定

- 术语按所属领域分类组织，同一领域内按字母顺序排列
- 英文术语保留原始大小写形式
- 缩写字段为空表示该术语无常用缩写
- 相关术语引用使用「中括号」标注，如 `[Gateway]`、`[Agent]`
- 带有 **(Deprecated)** 标记的术语表示已弃用或不推荐使用
- 带有 **(Experimental)** 标记的术语表示实验性功能

## 2. 核心概念术语

| ReAct | - | 推理与行动（Reasoning and Acting）范式，AI Agent 在执行任务时交替进行推理思考和工具调用行动。Lobster Loop 是 ReAct 范式在 MyOpenClaw 中的具体实现。 | AI/Agent | [Lobster Loop]、[Agent]、[CoT] |
| Agent（智能体） | - | 能够感知环境、自主决策并执行行动以完成目标的智能实体。在 MyOpenClaw 中，Agent 由 Agent Runtime 驱动，通过 Lobster Loop 自主循环处理用户请求。 | Agent Runtime | [Agent Runtime]、[Lobster Loop]、[Tool] |
| Gateway（网关） | - | MyOpenClaw 的核心控制平面，默认开放 18780 WebSocket 端口。负责接收所有渠道的消息、路由请求到 Agent Runtime、管理会话生命周期、执行鉴权与限流。是 Hub-Spoke 架构中的"Hub"。 | Gateway | [Hub-Spoke 架构]、[Channel]、[Session] |

| Tool（工具） | - | Agent 可调用的外部能力单元，用于执行具体操作（如网络搜索、文件操作、API 调用等）。工具通过 ToolRegistry 注册管理，具有标准化的输入输出 Schema 定义。 | Skill/Tools 工具执行层 | [ToolRegistry]、[Skill]、[Agent] |
| Skill（技能） | - | 高于 Tool 的能力抽象，是预定义的任务模板，可组合多个 Tool 完成复杂任务。技能以插件形式存在，支持动态加载和自定义开发。如"文件总结"、"日程管理"、"代码审查"等。 | Skill/Tools 工具执行层 | [Tool]、[ToolRegistry]、[Agent] |
| Memory（记忆） | - | MyOpenClaw 的信息持久化能力，分为短期会话记忆和长期向量记忆。短期记忆保存当前会话的对话上下文，长期记忆通过向量检索关联历史信息，使 Agent 具备跨会话的"记忆"能力。 | Memory 持久存储层 | [Session]、[Vector]、[Embedding] |

| ChannelProvider（渠道提供者） | - | 渠道适配器接口，每个具体渠道（Telegram、Discord 等）实现此接口。负责将平台特定消息协议转换为 MyOpenClaw 统一消息格式，以及将 Agent 的响应转换回平台特定格式发送。 | Channels | [Channel]、[Message]、[LLMAdapter] |
| LLMAdapter（LLM 适配器） | - | 大语言模型适配器，负责屏蔽不同 LLM 提供商（OpenAI、Claude、DeepSeek、本地模型）的 API 差异，提供统一的调用接口。支持自动故障切换到备用模型。 | Agent Runtime | [LLM]、[Agent]、[Orchestrator] |
| Orchestrator（编排器） | - | Agent Runtime 中的核心调度组件，负责编排 Lobster Loop 的各阶段执行顺序。协调感知、思考、规划、执行、观察、反思各阶段的输入输出，管理循环迭代和终止条件。 | Agent Runtime | [Lobster Loop]、[Planner]、[Agent] |
| Planner（规划器） | - | Lobster Loop 中规划阶段的核心组件，负责将用户的高层目标分解为可执行的任务步骤序列。Planner 根据当前上下文和可用工具，生成具体的执行计划。 | Agent Runtime | [Lobster Loop]、[Orchestrator]、[Tool] |
| Perception Module（感知模块） | - | Lobster Loop 中感知阶段的组件，负责解析用户输入消息、提取意图、识别上下文信息。是 Agent 与外部环境交互的"感官"。 | Agent Runtime | [Lobster Loop]、[Orchestrator] |

| CLI 客户端（Commander） | - | 基于 Commander 框架构建的命令行交互客户端，位于 `clients/cli/`。提供子命令体系（chat/send/sessions/tools 等），支持交互式对话、脚本化调用和管道输入，通过 HTTP/WebSocket 直连 Gateway。 | Clients | [Commander]、[Gateway]、[WebSocket] |

| Web 客户端 | - | 基于 React/Vue 构建的浏览器端图形界面客户端，位于 `clients/web/`。提供可视化的聊天界面、会话管理、设置面板，支持明暗主题和响应式布局，通过 WebSocket 直连 Gateway。 | Clients | [React]、[Gateway]、[WebSocket] |

## 4. 消息与协议术语

| 术语名称 | 缩写 | 定义说明 | 所属模块/领域 | 相关术语 |
|---------|------|------|-------------|---------|
| Message（消息结构体） | - | MyOpenClaw 内部统一的消息数据结构，所有渠道的消息在进入 Gateway 前都会被转换为 Message 格式。包含消息 ID、会话 ID、用户 ID、渠道来源、消息类型、消息内容、时间戳、元数据等字段。 | 消息协议 | [Channel]、[ChannelProvider]、[Session]、[Gateway] |
| Session（会话） | - | 一次连续对话的上下文单元。每个 Session 包含唯一的会话 ID、关联的用户 ID、渠道来源、消息历史列表和会话状态。Session 是 Agent 运行和记忆管理的基本单位。默认 24 小时过期。 | 消息协议 | [Message]、[Memory]、[Gateway]、[Agent] |
| Request 消息（请求消息） | - | 从渠道发送到 Gateway 的用户请求消息。包含用户输入内容、附件、上下文标识等信息。Request 消息触发 Agent 的 Lobster Loop 处理流程。 | 消息协议 | [Message]、[Response 消息]、[Event 消息]、[Gateway] |
| Response 消息（响应消息） | - | Agent 处理完成后通过 Gateway 返回给渠道的响应消息。包含 AI 生成的回复内容、调用的工具信息、执行状态等。 | 消息协议 | [Message]、[Request 消息]、[Gateway]、[Agent] |
| Event 消息（事件消息） | - | 系统内部的事件通知消息，用于异步通知。如定时任务触发事件、渠道状态变更事件、Agent 状态更新事件等。Event 消息不直接返回给用户，而是触发相应的处理逻辑。 | 消息协议 | [Message]、[Cron]、[Gateway] |
| WebSocket 协议 | WS | MyOpenClaw Gateway 使用的全双工通信协议，默认监听 18780 端口。支持持久连接、实时消息推送，是所有渠道与 Gateway 通信的基础协议。相比 HTTP 轮询，具有更低的延迟和更高的效率。 | 消息协议 | [Gateway]、[Channel]、[Message] |
| WebSocket Secure | WSS | WebSocket 的加密版本，使用 TLS/SSL 加密通信内容。生产环境中应通过 Nginx 反向代理将 WS 升级为 WSS，确保通信安全。 | 消息协议 | [WebSocket]、[Gateway]、[TLS] |
| Message ID（消息标识符） | - | 每条 Message 的唯一标识，采用 UUID v4 格式。用于消息追踪、去重和关联请求-响应对。 | 消息协议 | [Message]、[Session] |
| Session ID（会话标识符） | - | 每个 Session 的唯一标识，采用 `sess_` 前缀 + UUID 格式。用于关联同一会话内的所有消息，是记忆检索的索引键。 | 消息协议 | [Session]、[Message]、[Memory] |
| User ID（用户标识符） | - | 用户的唯一标识，由渠道提供。同一用户在不同渠道可能有不同的 User ID，通过多渠道绑定机制关联为同一用户身份。 | 消息协议 | [Session]、[Channel]、[多渠道绑定] |
| Payload（消息载荷） | - | Message 中实际承载业务数据的部分。根据消息类型不同，Payload 可以是文本内容、文件附件、工具调用参数等。 | 消息协议 | [Message]、[Request 消息] |
| Metadata（元数据） | - | Message 中附加的描述性信息，不属于核心业务数据。包含渠道来源、客户端信息、时间戳、自定义标签等，用于路由、过滤和审计。 | 消息协议 | [Message]、[审计日志] |
| Heartbeat（心跳） | - | WebSocket 连接的保活机制。客户端定期发送心跳消息，服务端回复确认，用于检测连接是否存活。默认间隔 30 秒，超过 90 秒未收到心跳则断开连接。 | 消息协议 | [WebSocket]、[Gateway] |
| ACK（确认应答） | - | 消息送达确认机制。Gateway 收到消息后返回 ACK 确认，确保消息不会因网络问题丢失。支持幂等处理，重复消息不会产生副作用。 | 消息协议 | [Message]、[WebSocket] |

## 5. 记忆与存储术语

| 术语名称 | 缩写 | 定义说明 | 所属模块/领域 | 相关术语 |
|---------|------|------|-------------|---------|
| Session 短期记忆 | - | 当前会话中的对话上下文，保存在内存或缓存中。包含最近的消息历史（默认 50 条），用于维持多轮对话的连贯性。会话结束后或过期后清除，不持久化。 | Memory 持久存储层 | [Session]、[Memory]、[Context Window] |
| Vector 向量记忆 | - | 将历史对话和知识转换为高维向量表示并存储，通过向量相似度检索实现语义关联的长期记忆机制。使 Agent 能"回忆"跨会话的相关历史信息。向量记忆持久化存储，不随会话结束而清除。 | Memory 持久存储层 | [Embedding]、[向量检索]、[TopK]、[Memory] |
| Persist 持久化层 | - | Memory 存储层中负责数据持久化的底层组件。将 Session 数据、消息历史等写入磁盘（SQLite/PostgreSQL），确保服务重启后数据不丢失。 | Memory 持久存储层 | [Memory]、[Session]、[SQLite] |
| Embedding（嵌入向量） | - | 将文本数据映射为高维浮点数向量的过程。MyOpenClaw 使用 LLM 提供商的 Embedding 模型（如 OpenAI text-embedding-3-small，1536 维）将对话文本转换为向量，用于后续的相似度检索。 | Memory/AI | [Vector]、[向量检索]、[LLM] |
| 向量检索 | - | 在向量数据库中查找与查询向量最相似的 TopK 个向量的过程。通过计算向量间的余弦相似度或欧氏距离，找出语义最相关的历史记忆。 | Memory 持久存储层 | [Vector]、[Embedding]、[TopK]、[HNSW] |
| TopK | - | 向量检索中返回的最相似结果数量参数。默认值为 5，表示检索最相关的 5 条记忆。TopK 值越大，召回的信息越多，但计算开销和 Token 消耗也越大。 | Memory 持久存储层 | [向量检索]、[Vector]、[Embedding] |
| 向量存储 | - | 存储向量数据的后端系统。MyOpenClaw 支持多种向量存储方案：本地文件存储（小规模）、pgvector（PostgreSQL 插件）、Chroma（专用向量数据库）等。 | Memory 持久存储层 | [Vector]、[pgvector]、[Chroma] |
| pgvector | - | PostgreSQL 的向量检索扩展插件，使 PostgreSQL 兼具关系型数据库和向量数据库的能力。支持 HNSW 和 IVFFlat 索引，适合中等规模的向量检索场景。 | Memory/存储 | [Vector]、[向量检索]、[HNSW]、[PostgreSQL] |
| HNSW 索引 | - | 分层可导航小世界图（Hierarchical Navigable Small World）索引，一种高性能近似最近邻搜索算法。通过多层图结构实现快速向量检索，在召回率和查询速度之间取得良好平衡。 | Memory/存储 | [向量检索]、[pgvector]、[TopK] |
| Chroma | - | 开源的专用向量数据库，专为 AI 应用设计。提供高效的向量存储和检索能力，适合需要独立向量数据库的场景。 | Memory/存储 | [Vector]、[向量检索]、[向量存储] |
| 上下文摘要 | - | 当对话历史超过 LLM 的 Context Window 限制时，自动将早期对话内容摘要为简短总结的机制。在保留关键信息的同时减少 Token 消耗，延长可用对话长度。 | Memory/AI | [Context Window]、[Token]、[Session] |

## 6. AI 与 LLM 术语

| 术语名称 | 缩写 | 定义说明 | 所属模块/领域 | 相关术语 |
|---------|------|------|-------------|---------|
| LLM（大语言模型） | LLM | Large Language Model，基于深度学习的大规模语言模型，能够理解和生成人类语言文本。MyOpenClaw 支持多种 LLM 提供商：OpenAI（GPT 系列）、Claude、DeepSeek 以及本地开源模型。 | AI/LLM | [LLMAdapter]、[Token]、[Context Window]、[Prompt] |
| CoT（思维链） | CoT | Chain of Thought，思维链推理范式。LLM 在回答问题时展示逐步推理过程，而非直接给出答案。通过展示中间推理步骤，提高复杂问题的回答准确率。Lobster Loop 的思考阶段即应用了 CoT 思想。 | AI/LLM | [Lobster Loop]、[ReAct]、[LLM] |
| Prompt（提示词） | - | 发送给 LLM 的输入文本，引导模型生成期望的输出。在 MyOpenClaw 中，Prompt 包含用户消息、系统指令、上下文信息、工具定义等，经过 LLMAdapter 组装后发送给 LLM。 | AI/LLM | [System Prompt]、[LLM]、[Token]、[Context Window] |
| System Prompt（系统提示词） | - | 预设的指令性 Prompt，定义 AI 助手的角色、行为规范、能力边界和输出格式。在会话开始时注入，贯穿整个对话过程，确保 AI 助手的回复符合预期。 | AI/LLM | [Prompt]、[LLM]、[Agent] |
| Token（词元） | - | LLM 处理文本的基本单位。一个 Token 大致对应 0.75 个英文单词或 0.5 个中文字符。Token 数量影响 LLM 的处理速度和 API 费用。MyOpenClaw 监控 Token 消耗量以控制成本。 | AI/LLM | [LLM]、[Context Window]、[Prompt] |
| Context Window（上下文窗口） | - | LLM 单次请求能处理的最大 Token 数量。如 GPT-4o 的 Context Window 为 128K Token。当对话历史超过此限制时，MyOpenClaw 通过上下文摘要机制压缩历史内容。 | AI/LLM | [Token]、[上下文摘要]、[Session]、[Prompt] |
| Temperature（温度参数） | - | 控制 LLM 输出随机性的参数，取值范围 0-2。值越低输出越确定和保守，值越高输出越发散和有创意。MyOpenClaw 默认设为 0.7，可通过配置调整。 | AI/LLM | [LLM]、[Prompt] |
| Embedding Model（嵌入模型） | - | 将文本转换为向量表示的专用模型。与对话用 LLM 不同，Embedding Model 专门优化用于生成语义向量。MyOpenClaw 默认使用 OpenAI text-embedding-3-small（1536 维）。 | AI/LLM | [Embedding]、[Vector]、[LLM] |
| Function Calling（函数调用） | - | LLM 的能力之一，模型能根据用户意图选择并调用预定义的函数（工具），并以结构化格式返回调用参数。MyOpenClaw 利用此能力实现 Agent 的工具调用。 | AI/LLM | [Tool]、[LLMAdapter]、[Schema 校验] |
| Few-Shot Prompting（少样本提示） | - | 在 Prompt 中提供少量示例（通常 3-5 个），引导 LLM 按照示例的格式和风格生成输出。MyOpenClaw 在技能调用时使用 Few-Shot Prompting 提高输出质量。 | AI/LLM | [Prompt]、[Skill]、[LLM] |
| Fine-tuning（微调） | - | 在预训练模型基础上使用特定领域数据进行进一步训练的过程。MyOpenClaw 本身不提供微调功能，但支持连接经过微调的本地模型。 | AI/LLM | [LLM]、[本地模型] |
| 本地模型 | - | 部署在用户本地服务器上的开源 LLM，如通过 Ollama 部署的 Llama、Qwen、Mistral 等。使用本地模型可避免 API 调用费用和数据外传，但需要较高的硬件配置（建议 GPU）。 | AI/LLM | [LLM]、[LLMAdapter]、[Ollama] |
| Ollama | - | 本地大模型运行框架，支持一键部署和运行各种开源 LLM。MyOpenClaw 通过 LLMAdapter 集成 Ollama，实现对本地模型的调用。 | AI/LLM | [本地模型]、[LLM]、[LLMAdapter] |
| 模型回退 | - | 当主 LLM 提供商不可用时，自动切换到备用 LLM 提供商的机制。如 OpenAI API 超时时自动切换到 Claude，确保服务可用性。在 config.yaml 的 `llm.fallback` 中配置。 | AI/LLM | [LLM]、[LLMAdapter] |
| 流式输出 | - | LLM 逐 Token 返回生成结果的机制，而非等待完整结果再返回。MyOpenClaw 支持流式输出，使用户能更早看到 AI 的回复，提升交互体验。 | AI/LLM | [LLM]、[LLMAdapter]、[Response 消息] |

## 7. 安全术语

| 术语名称 | 缩写 | 定义说明 | 所属模块/领域 | 相关术语 |
|---------|------|------|-------------|---------|
| Token 鉴权 | - | Gateway 的身份认证机制。客户端在连接 Gateway 时需在请求头中携带预配置的 Token，Gateway 验证通过后才允许访问。默认请求头名称为 `X-MyOpenClaw-Token`。 | 安全 | [Gateway]、[API 认证]、[Token] |
| 限流 | - | 防止请求过载的保护机制。Gateway 内置令牌桶限流器，默认每 60 秒允许 100 次请求，超限请求被拒绝并返回 429 状态码。可在 config.yaml 中配置限流参数。 | 安全 | [Gateway]、[Rate Limit]、[Token 鉴权] |
| 沙箱隔离 | - | 工具执行的安全隔离机制。Agent 调用 Tool 时在受限环境中执行，限制文件系统访问、网络访问和系统调用权限，防止恶意代码影响宿主系统。支持 process 和 docker 两种沙箱类型。 | 安全 | [Tool]、[Skill]、[安全加固] |
| Schema 校验 | - | 对工具调用的输入参数进行结构化验证的机制。每个 Tool 定义输入输出的 JSON Schema，执行前验证参数类型和格式，拒绝非法输入，防止注入攻击和参数错误。 | 安全 | [Tool]、[ToolRegistry]、[Function Calling] |
| 审计日志 | - | 记录系统所有关键操作的日志，用于安全审计和合规追溯。记录内容包括操作者、操作时间、操作类型、操作结果等。默认保留 90 天，存储在独立目录中。 | 安全 | [日志管理]、[Token 鉴权] |
| CORS（跨域资源共享） | - | Cross-Origin Resource Sharing，浏览器的安全策略机制。Gateway 通过 CORS 配置控制哪些域名可以访问 API，防止跨站请求伪造。在 config.yaml 的 `gateway.cors` 中配置允许的来源。 | 安全 | [Gateway]、[WebUI] |
| API Key 保护 | - | 对 LLM API Key 等敏感凭证的保护措施。MyOpenClaw 支持通过环境变量注入、Docker Secrets、HashiCorp Vault 等方式管理 API Key，避免明文存储在配置文件中。 | 安全 | [LLM]、[敏感信息管理]、[环境变量] |
| HTTPS 终止 | - | 在反向代理层（如 Nginx）解密 HTTPS 流量后，以 HTTP 转发给后端服务的机制。MyOpenClaw 本身使用 HTTP/WebSocket，通过 Nginx 提供 HTTPS 对外服务，简化证书管理。 | 安全 | [Nginx]、[TLS]、[Gateway] |
| TLS（传输层安全） | - | Transport Layer Security，加密通信协议。生产环境应通过 Nginx 启用 TLS，确保客户端与服务器之间的通信内容不被窃听或篡改。推荐使用 TLS 1.2 或 1.3。 | 安全 | [HTTPS 终止]、[WSS]、[Nginx] |
| 权限隔离 | - | MyOpenClaw 运行时建议使用非 root 用户（UID 1001）的权限隔离机制。即使服务被攻破，攻击者也仅获得有限权限，降低安全风险。在本地启动或源码运行时默认启用。 | 安全 | [沙箱隔离]、[安全加固] |
| 输入过滤 | - | 对用户输入消息进行安全过滤的机制。检测并过滤潜在的 Prompt 注入攻击、恶意代码等内容，防止用户输入影响系统指令或触发非预期行为。 | 安全 | [Schema 校验]、[沙箱隔离] |
