## 1. 项目定位

MyOpenClaw 是一个**本地优先、自托管**的开源 AI Agent 框架，基于 TypeScript + Node.js 开发，采用 MIT 开源协议。它的核心定位是：在用户本地设备或私有服务器上运行的**个人自主 AI 助手**，不依赖任何第三方云服务即可完成完整的智能体任务执行。

与云端 AI Agent 平台不同，MyOpenClaw 将所有数据——对话历史、长期记忆、文件操作、配置信息——默认存储在本地，从架构层面保障了数据隐私。同时，系统内置的 Gateway 网关作为常驻守护进程，默认开放 `18780` WebSocket 端口，作为所有内外流量的统一通信入口。

MyOpenClaw 支持接入 20+ 社交与办公渠道（Telegram、Discord、飞书、微信、WebUI 等），提供三种原生客户端（Web 前端界面、基于 Ink 的 TUI 终端界面、基于 Commander 的 CLI 命令行工具），可对接多种 LLM 大模型（OpenAI GPT、Claude、DeepSeek、本地开源模型），并通过自主任务循环（Lobster Loop / ReAct 模式）实现多步骤复杂任务的自动执行。

## 2. 核心特性

### 2.1 中心化网关管控

系统唯一常驻守护进程 Gateway 统一收敛所有内外流量，集中处理鉴权、路由、状态调度、安全限流和日志审计。所有渠道、Agent、工具之间不存在直接调用关系，全部通过网关中转，从架构层面消除了多进程分散管理带来的状态不一致风险。

### 2.2 插件化渠道与工具

Channels 渠道层和 Tools 工具层均采用统一接口标准（`ChannelProvider`、`ToolRegistry`），新增渠道或工具无需修改核心逻辑。渠道支持热插拔，工具通过注册中心统一管理，LLM 仅通过注册中心发起调用。

### 2.3 本地数据隐私

所有记忆数据（短期会话上下文、长期向量记忆）、文件操作记录、对话历史默认存储在本地文件系统或轻量数据库中。网关和 Agent 重启后自动从持久化层加载历史数据，不向任何第三方服务上传用户数据。

### 2.4 自主智能体闭环

内置 Lobster 自主循环，实现完整的 `感知 → 思考 → 规划 → 执行 → 观察 → 反思` 六阶段闭环。Agent 接收用户指令后可自主拆解任务、编排工具调用、根据执行结果调整策略，无需人工分段干预即可完成多步骤复杂任务。

### 2.5 低耦合可扩展

五层架构各层之间单向依赖，模块间通过标准化接口通信。Skill 业务技能以纯 Markdown 描述文件定义，无需编写代码即可扩展 Agent 的业务能力。新增 LLM 模型只需实现统一的适配器接口。

## 4. 适用场景

### 4.1 个人智能助手

将 MyOpenClaw 部署在个人电脑或家用服务器上，通过 Telegram、微信等即时通讯渠道与 AI 助手交互。助手可读取本地文件、执行系统命令、管理日程、检索历史对话，成为真正了解你个人上下文的 AI 管家。

### 4.2 团队办公自动化

接入飞书、钉钉等办公平台，为团队提供自动化办公能力。通过 Skill 技能定义审批流程、报表生成、Issue 管理等业务场景，团队成员在群聊中发送自然语言指令即可触发自动化任务执行。

### 4.3 开发者工具集成

通过 CLI 渠道接入开发工作流，Agent 可执行代码审查、运行测试、管理 Git 仓库、查阅文档。Tools 工具层提供 Shell 执行、文件操作、浏览器自动化等原子能力，支持构建自定义开发辅助工具链。

### 4.4 定时任务调度

利用 Gateway 内置的 Cron 定时调度器，配置周期性自动任务。系统在到达执行时间后自动创建临时 Agent 会话，执行预设技能，并将结果推送至指定渠道。适用于每日报告生成、数据监控告警、定期数据同步等场景。

## 5. 系统组成

MyOpenClaw 采用 Hub-Spoke 中枢六层架构，并在渠道层之上扩展了客户端层，自上而下分为：

```
┌─────────────────────────────────────────────┐
│     Clients 客户端层（用户交互界面）           │
│  Web 前端 / TUI 终端界面 / CLI 命令行工具      │
├─────────────────────────────────────────────┤
│         Channels 渠道接入层（IO 外层）         │
│    统一封装外部消息渠道，输出标准化 Message      │
├─────────────────────────────────────────────┤
│       Gateway 网关层（全局中枢控制平面）        │
│    鉴权、路由、状态调度、安全限流、审计日志       │
├─────────────────────────────────────────────┤
│      Agent Runtime 智能体运行时（推理大脑）     │
│    Lobster 自主循环、LLM 调用、任务拆解编排     │
├─────────────────────────────────────────────┤
│     Skill/Tools 工具执行层（原子能力）         │
│    文件、Shell、浏览器、数据库、网络请求        │
├─────────────────────────────────────────────┤
│       Memory 持久存储层（上下文底座）          │
│    会话历史、向量记忆、配置、运行状态持久化      │
└─────────────────────────────────────────────┘
```

客户端层通过 WebSocket / HTTP 协议与 Gateway 直接通信，支持实时双向消息推送，提供可视化的交互体验。

各层的详细职责和模块划分请参阅 [01-架构设计文档](01-架构设计文档.md)。

## 6. 与同类项目对比

| 特性 | MyOpenClaw | 云端 Agent 平台 | 传统聊天机器人 |
|------|----------|-----------------|----------------|
| 数据存储位置 | 本地优先 | 云端服务器 | 云端服务器 |
| 数据隐私 | 完全自主可控 | 依赖平台政策 | 依赖平台政策 |

| 开源协议 | MIT | 多为闭源 | 多为闭源 |
| 定制化程度 | 完全可定制 | 有限 | 无 |
