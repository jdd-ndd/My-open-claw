## 1. 开发环境搭建

### 1.1 基础环境要求

| 工具 | 版本要求 | 说明 |
|------|----------|------|
| **Node.js** | 20 LTS（>= 20.10.0） | 必须使用 LTS 版本，需支持原生 `fetch`、`structuredClone`、`crypto.randomUUID` |
| **pnpm** | >= 9.0.0 | 包管理器（项目强制使用 pnpm，利用其 workspace 与硬链接能力） |
| **TypeScript** | >= 5.4.0 | 编程语言，项目内置，无需全局安装 |
| **Git** | >= 2.40 | 版本控制 |
| **Docker** | >= 24.0（可选） | 用于运行集成测试依赖（Redis、PostgreSQL、向量数据库） |

**操作系统支持**：

- macOS 13+（Apple Silicon / Intel）
- Ubuntu 22.04+ / Debian 12+
- Windows 11（需启用 WSL2，推荐在 WSL2 中开发）

### 1.2 安装步骤

```bash
# 1. 安装 Node.js 20 LTS（推荐使用 nvm 管理版本）
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.39.7/install.sh | bash
nvm install 20
nvm use 20
node -v  # 应输出 v20.x.x

# 2. 启用 pnpm（Node.js 内置 corepack）
corepack enable
corepack prepare pnpm@latest --activate
pnpm -v  # 应输出 9.x.x

# 3. 克隆仓库（以 fork 后的仓库为例）
git clone https://github.com/<your-username>/myopenclaw.git
cd "My open claw/server"

# 4. 添加上游仓库（用于同步官方更新）
git remote add upstream https://github.com/myopenclaw/myopenclaw.git

# 5. 安装依赖
npm install

# 6. 复制环境变量模板
cp .env.example .env
# 编辑 .env，至少配置 LLM API Key

# 7. 构建项目（首次需全量构建）
pnpm build

# 8. 启动开发服务
pnpm dev
```

## 2. 代码规范

### 2.1 TypeScript 编码规范

#### 2.1.1 命名约定

| 元素 | 规范 | 示例 |
|------|------|------|
| 变量、函数 | camelCase 小驼峰 | `sendMessage`、`sessionId` |
| 常量 | UPPER_SNAKE_CASE 大写下划线 | `DEFAULT_PORT`、`MAX_TOKENS` |
| 类、接口、类型 | PascalCase 大驼峰 | `AgentRuntime`、`Message` |
| 枚举 | PascalCase，成员 PascalCase | `enum MessageType { Text, Image }` |
| 私有成员 | camelCase，前缀不加 `_` | `private sessionId` |
| 文件名 | kebab-case 小写下划线 | `agent-runtime.ts`、`message.schema.ts` |
| 类型文件 | 与导出类型同名 | `Message` 类型 → `message.ts` |

**接口命名例外**：接口不加 `I` 前缀（如用 `Message` 而非 `IMessage`），符合 TypeScript 社区惯例。

#### 2.1.2 类型使用规范

```typescript
// ✅ 推荐：显式定义类型，避免 any
interface User {
  id: string;
  name: string;
  email: string;
}

// ✅ 推荐：使用 unknown 而非 any，强制类型检查
function parse(input: unknown): User {
  // 使用类型守卫收窄
  if (typeof input === 'object' && input !== null && 'id' in input) {
    return input as User;
  }
  throw new Error('Invalid input');
}

// ❌ 禁止：使用 any
function badParse(input: any): any {
  return input; // 类型安全丧失
}

// ✅ 推荐：使用字面量联合类型而非枚举（tree-shaking 友好）
type Status = 'active' | 'idle' | 'closed';

// ✅ 推荐：使用 type 别名定义联合类型，interface 定义对象结构
type MessageType = 'text' | 'image' | 'audio';
interface Message {
  type: MessageType;
  content: string;
}

// ✅ 推荐：使用 readonly 标记不可变字段
interface Session {
  readonly id: string; // 创建后不可变
  status: SessionStatus; // 可变
}

// ✅ 推荐：使用 as const 断言定义常量对象
const CONFIG = {
  port: 18780,
  timeout: 30000,
} as const;
// CONFIG.port 类型为 18780（字面量），而非 number
```

#### 2.1.3 异步处理规范

```typescript
// ✅ 推荐：始终使用 async/await，避免 .then() 链
async function fetchSession(id: string): Promise<Session> {
  const session = await sessionStore.get(id);
  if (!session) {
    throw notFoundError(ErrorCode.SESSION_NOT_FOUND, '会话不存在');
  }
  return session;
}

// ❌ 禁止：混合使用 Promise 链与 async/await
async function badFetch(id: string) {
  return sessionStore.get(id).then((s) => s); // 风格不一致
}

// ✅ 推荐：并发任务使用 Promise.all
const [session, tools, memory] = await Promise.all([
  getSession(id),
  listTools(),
  getMemory(id),
]);

// ✅ 推荐：处理边界情况与错误
async function riskyOperation(): Promise<Result> {
  try {
    return await externalApi.call();
  } catch (error) {
    // 区分可重试与不可重试错误
    if (error instanceof AppError && error.retryable) {
      return retry(() => externalApi.call(), { maxRetries: 3 });
    }
    throw error;
  }
}

// ✅ 推荐：使用 AbortController 支持取消
async function longRunningTask(signal: AbortSignal): Promise<void> {
  for (const item of items) {
    if (signal.aborted) throw new Error('Task aborted');
    await processItem(item, signal);
  }
}
```

#### 2.1.4 ESLint 核心规则

项目使用严格 ESLint 配置，关键规则：

| 规则 | 级别 | 说明 |
|------|------|------|
| `@typescript-eslint/no-explicit-any` | error | 禁止使用 any |
| `@typescript-eslint/no-unused-vars` | error | 禁止未使用变量 |
| `@typescript-eslint/explicit-function-return-type` | warn | 公共函数需显式返回类型 |
| `@typescript-eslint/consistent-type-imports` | error | 类型导入使用 `import type` |
| `no-console` | warn | 禁止 console，使用 logger |
| `prefer-const` | error | 优先 const |
| `eqeqeq` | error | 强制严格相等 |

### 2.2 文件组织规范

```
src/
├── core/                       # 公共模块（见 08 文档）

│   ├── base/                   # 渠道基类与接口
```

```typescript
// ✅ 推荐：一个文件一个主要导出

export class AgentRuntime { ... }

// src/core/utils/time.ts
```

## 3. 项目构建与运行

### 3.1 开发模式

开发模式使用 `tsx` 进行即时 TypeScript 转译，配合 `--watch` 实现热重载：

```bash
# 启动开发服务（热重载）
npm run dev

# 等价于
tsx watch src/index.ts
```

开发模式特性：

- **热重载**：文件修改自动重启，保留进程级状态需自行处理。
- **Source Map**：错误堆栈映射到 TypeScript 源码。
- **环境变量**：自动加载 `.env` 文件。
- **详细日志**：日志级别默认 `debug`。

### 3.2 生产构建

```bash
# 全量构建
npm run build

# 等价于
tsc -p tsconfig.build.json

# 生产模式启动
npm start

# 等价于
node dist/index.js

# 运行测试
npm test

# 等价于
vitest run
```

构建产物输出到 `dist/` 目录，使用 CommonJS 或 ESM（根据 `tsconfig` 配置）。

**构建优化**：

```jsonc
// tsconfig.build.json
{
  "extends": "./tsconfig.json",
  "compilerOptions": {
    "declaration": true,           // 生成 .d.ts
    "declarationMap": true,        // 生成 declaration source map
    "sourceMap": true,             // 生成 source map
    "removeComments": false,       // 保留注释（JSDoc 用于 IDE 提示）
    "noEmitOnError": true          // 类型错误时不输出
  },
  "exclude": ["**/*.test.ts", "**/*.spec.ts", "tests/**"]
}
```

## 4. 测试规范

### 4.1 测试分层策略

MyOpenClaw 采用经典测试金字塔：

```
                    /\
                   /  \        E2E 测试（少量）
                  /----\       端到端，模拟真实用户场景
                 /      \
                / 集成  \      集成测试（适量）
               / 测试     \     模块间协作，真实依赖
              /------------\
             /              \
            /    单元测试      \  单元测试（大量）
           /                  \ 隔离的函数/类测试
          /____________________\
```

| 层级 | 占比 | 框架 | 运行速度 | 依赖 |
|------|------|------|----------|------|
| 单元测试 | 70% | Vitest | 毫秒级 | Mock 全部外部依赖 |
| 集成测试 | 20% | Vitest + Testcontainers | 秒级 | 真实数据库等 |
| E2E 测试 | 10% | Vitest + Playwright | 分钟级 | 完整系统 |

### 4.2 单元测试

**框架选择**：[Vitest](https://vitest.dev/)（与 Vite 生态一致，速度快，API 与 Jest 兼容）。

**测试文件位置**：与源文件同目录，命名 `<name>.test.ts`。

```typescript
// src/core/utils/retry.test.ts
import { describe, it, expect, vi } from 'vitest';
import { retry } from './retry';

describe('retry', () => {
  it('首次成功时不重试', async () => {
    const fn = vi.fn().mockResolvedValue('success');
    const result = await retry(fn);
    expect(result).toBe('success');
    expect(fn).toHaveBeenCalledTimes(1);
  });

  it('达到最大重试次数后抛出最后一个错误', async () => {
    const error = new Error('fail');
    const fn = vi.fn().mockRejectedValue(error);
    await expect(retry(fn, { maxRetries: 3, initialDelayMs: 0 })).rejects.toThrow('fail');
    expect(fn).toHaveBeenCalledTimes(4); // 1 + 3 重试

  it('shouldRetry 返回 false 时立即抛出', async () => {

      retry(fn, {
        maxRetries: 5,
        initialDelayMs: 0,
        shouldRetry: () => false,
      })
    ).rejects.toThrow('non-retryable');
    expect(fn).toHaveBeenCalledTimes(1);
  });

  it('使用指数退避延迟', async () => {
    vi.useFakeTimers();
    const fn = vi.fn().mockRejectedValueOnce(new Error('fail')).mockResolvedValue('ok');
    const promise = retry(fn, {
      maxRetries: 3,
      initialDelayMs: 100,
      backoffFactor: 2,
    });
    // 第一次重试在 100ms 后
    await vi.advanceTimersByTimeAsync(100);
    // 第二次不需要，因为第二次调用成功
    const result = await promise;
    expect(result).toBe('ok');
    vi.useRealTimers();
  });
});
```

```typescript
/** 辅助函数：发送 WebSocket 请求并等待响应 */
function sendRequest(ws: WebSocket, method: string, params: object): Promise<any> {
  return new Promise((resolve) => {
    const id = Math.random().toString();
    const handler = (data: string) => {
      const msg = JSON.parse(data);
      if (msg.type === 'response' && msg.id === id) {
        ws.off('message', handler);
        resolve(msg);
      }
    };
    ws.on('message', handler);
    ws.send(JSON.stringify({ type: 'request', id, method, params }));
  });
}
```

## 6. 贡献流程

### 6.1 Fork → Branch → Commit → PR 流程

```
[Fork 官方仓库到个人账号]
         │
         ▼
[git clone 个人 fork]
         │
         ▼
[git remote add upstream 官方仓库]  ← 添加上游，便于同步
         │
         ▼
[git checkout -b feature/xxx]  ← 从 main 创建特性分支
         │
         ▼
[开发 + 本地测试通过]
         │
         ▼
[git commit（遵循 Commit 规范）]
         │
         ▼
[git push origin feature/xxx]
         │
         ▼
[GitHub 发起 Pull Request → upstream/main]
         │
         ▼
[CI 检查通过（lint / typecheck / test）]
         │
         ▼
[Code Review（至少 1 位 Reviewer approve）]
         │
         ▼
[Squash Merge 到 main]
         │
         ▼
[删除特性分支]
```

**分支命名规范**：

| 前缀 | 用途 | 示例 |
|------|------|------|
| `feature/` | 新功能 | `feature/add-slack-channel` |
| `fix/` | Bug 修复 | `fix/memory-leak-in-gateway` |
| `refactor/` | 重构 | `refactor/agent-react-loop` |
| `docs/` | 文档 | `docs/update-api-reference` |
| `test/` | 测试 | `test/add-core-coverage` |
| `chore/` | 杂项 | `chore/upgrade-dependencies` |

### 6.2 Commit Message 规范

项目遵循 [Conventional Commits](https://www.conventionalcommits.org/) 规范：

```
<type>(<scope>): <subject>

<body>

<footer>
```

**type 类型**：

| type | 说明 |
|------|------|
| `feat` | 新功能 |
| `fix` | Bug 修复 |
| `docs` | 文档变更 |
| `style` | 代码格式（不影响逻辑） |
| `refactor` | 重构（非新功能、非修复） |
| `perf` | 性能优化 |
| `test` | 测试相关 |
| `chore` | 构建/工具/依赖变更 |
| `ci` | CI 配置 |
| `revert` | 回滚 |

**示例**：

```
feat(gateway): 新增 WebSocket 心跳超时检测

Gateway 现在会检测客户端心跳，90 秒无响应自动断开连接，
避免僵尸连接占用资源。

Closes #123
```

```
fix(memory): 修复高并发下记忆检索竞态条件

多个并发请求同时检索记忆时，存在 check-then-act 竞态，
导致重复写入。改为使用数据库事务 + 唯一约束解决。

Fixes #456
```

**禁止事项**：

- 禁止 `git commit -m "update"` 这类无意义信息。
- 禁止一个 commit 混合多个不相关变更。
- 禁止在 commit message 中放置大量代码（放 PR 描述中）。

### 6.3 PR Review 标准

PR 合并需满足以下全部条件：

| 检查项 | 要求 |
|--------|------|
| CI 通过 | lint、typecheck、test 全部绿色 |
| 测试覆盖 | 新增代码有对应测试，覆盖率不下降 |
| 代码规范 | 符合 ESLint 规则，无 Prettier 格式问题 |
| Commit 规范 | 符合 Conventional Commits |
| 文档更新 | API 变更需更新对应文档 |
| 向后兼容 | 不破坏现有 API（除非 major 版本） |
| Reviewer 批准 | 至少 1 位 Core Team 成员 approve |
| 变更范围 | 单个 PR 聚焦单一职责，建议 < 500 行 |

**Review 关注点**：

1. **正确性**：逻辑是否正确，边界条件是否处理。
2. **安全性**：是否有注入、越权、信息泄露风险。
3. **性能**：是否有 N+1 查询、不必要的同步操作、内存泄漏。
4. **可读性**：命名是否清晰，复杂逻辑是否有注释。
5. **可测试性**：代码是否便于编写单元测试。

### 8.4 新增 LLM 适配器

新增 LLM 适配器需实现 `LLMAdapter` 接口，对接不同的 LLM 服务。

```typescript
// src/agent/adapters/claude.ts
import { LLMAdapter, type LLMRequest, type LLMResponse } from '@/agent/adapters/base';

/**
 * Claude LLM 适配器
 * 对接 Anthropic Claude API
 */
export class ClaudeAdapter implements LLMAdapter {
  readonly model: string;
  private apiKey: string;

  constructor(config: { model: string; apiKey: string }) {
    this.model = config.model;
    this.apiKey = config.apiKey;
  }

  async chat(request: LLMRequest): Promise<LLMResponse> {
    const response = await fetch('https://api.anthropic.com/v1/messages', {
      method: 'POST',
      headers: {
        'x-api-key': this.apiKey,
        'anthropic-version': '2023-06-01',
        'Content-Type': 'application/json',
      },
      body: JSON.stringify({
        model: this.model,
        messages: request.messages,
        tools: request.tools,
        max_tokens: request.maxTokens,
      }),
    });

    const data = await response.json();
    // 转换为统一的 LLMResponse 格式
    return {
      content: data.content[0].text,
      toolCalls: data.content
        .filter((c: any) => c.type === 'tool_use')
        .map((c: any) => ({ toolName: c.name, arguments: c.input, callId: c.id })),
      tokensIn: data.usage.input_tokens,
      tokensOut: data.usage.output_tokens,
    };
  }

  /** 流式响应 */
  async *chatStream(request: LLMRequest): AsyncGenerator<LLMStreamChunk> {
    // 实现 SSE 流式解析
  }
}
```

## 9. 性能优化指南

### 9.1 性能指标基线

| 指标 | 基线值 | 优秀值 | 说明 |
|------|--------|--------|------|
| Gateway 请求处理延迟 | < 5ms | < 2ms | 不含 LLM 调用 |
| 消息 Schema 校验延迟 | < 1ms | < 0.5ms | 单条消息 |
| 记忆检索延迟（短期） | < 10ms | < 5ms | 最近 20 条 |
| 记忆检索延迟（向量） | < 50ms | < 30ms | topK=5 |
| 工具执行调度延迟 | < 2ms | < 1ms | 不含工具自身耗时 |
| 单连接内存占用 | < 50KB | < 30KB | 每 WebSocket 连接 |
| 单会话内存占用 | < 500KB | < 200KB | 含上下文 |
| 并发会话数（单机） | >= 1000 | >= 5000 | 8C16G 基准 |

### 9.2 优化策略

#### 9.2.1 减少内存分配

```typescript
// ❌ 避免：循环内频繁创建对象
for (const item of items) {
  const result = { id: item.id, name: item.name, processed: true }; // 每次新建
  process(result);
}

// ✅ 优化：复用对象
const result: Record<string, unknown> = {};
for (const item of items) {
  result.id = item.id;
  result.name = item.name;
  result.processed = true;
  process(result);
}
```

#### 9.2.2 批量操作

```typescript
// ❌ 避免：N+1 查询
for (const sessionId of sessionIds) {
  const session = await memory.get(sessionId); // N 次查询
}

// ✅ 优化：批量查询
const sessions = await memory.getMany(sessionIds); // 1 次查询
```

#### 9.2.3 缓存

```typescript
// 使用 LRU 缓存热点数据
import { LRUCache } from 'lru-cache';

const sessionCache = new LRUCache<string, Session>({
  max: 1000,           // 最多缓存 1000 个会话
  ttl: 5 * 60 * 1000,  // 5 分钟过期
});

async function getSession(id: string): Promise<Session> {
  const cached = sessionCache.get(id);
  if (cached) return cached;

  const session = await sessionStore.get(id);
  sessionCache.set(id, session);
  return session;
}
```

```typescript
// ✅ 并发独立任务
```

## 10. 安全开发规范

### 10.1 输入校验

**所有外部输入必须经过 Schema 校验，绝不信任客户端数据。**

```typescript
// ✅ 推荐：使用 TypeBox 在入口校验
import { createTypeBoxValidator } from '@/core/schemas';
import { SendMessageSchema } from '@/schemas';

const validator = createTypeBoxValidator(SendMessageSchema);

function handleSendMessage(raw: unknown) {
  // 校验失败抛出 ValidationError，不会进入业务逻辑
  const params = validator.validate(raw);
  // params 已类型安全
}

// ✅ 推荐：限制输入大小
function validateAttachment(attachment: unknown) {
  if (attachment.size > 10 * 1024 * 1024) {
    throw validationError('附件超过 10MB 限制', []);
  }
}

// ✅ 推荐：防 ReDoS（正则拒绝服务）
// 避免使用易回溯的正则，使用安全工具校验
import safeRegex from 'safe-regex';
if (!safeRegex(userPattern)) {
  throw validationError('不安全的正则表达式', []);
}
```

### 10.2 密钥与凭证管理

```typescript
// ❌ 禁止：硬编码密钥
const API_KEY = 'sk-1234567890abcdef';

// ❌ 禁止：密钥写入代码或日志
log.info({ apiKey }, '使用 API Key'); // 泄露！

// ✅ 推荐：从环境变量读取
const API_KEY = process.env.LLM_API_KEY;
if (!API_KEY) throw new Error('未配置 LLM_API_KEY');

// ✅ 推荐：使用密钥管理服务（生产环境）
import { SecretsManager } from '@/core/secrets';
const apiKey = await SecretsManager.get('llm-api-key');

// ✅ 推荐：日志脱敏
log.info({ apiKey: maskKey(apiKey) }, '使用 API Key');
// 输出：apiKey: "sk-****cdef"

function maskKey(key: string): string {
  if (key.length <= 8) return '****';
  return key.slice(0, 3) + '****' + key.slice(-4);
}
```

### 10.3 工具执行沙箱

工具是 Agent 调用外部能力的通道，必须沙箱化执行，防止恶意代码。

```typescript
// ✅ 工具执行需满足：
// 1. 超时限制（默认 30s）
// 2. 资源限制（CPU、内存）
// 3. 权限隔离（最小权限原则）
// 4. 审计日志

async function executeToolSafely(tool: Tool, args: unknown, ctx: ToolContext) {
  // 1. 校验入参
  const validatedArgs = validateToolInput(tool, args);

  // 2. 权限检查
  if (!ctx.session.config.allowedTools?.includes(tool.name)) {
    throw new AppError({
      code: ErrorCode.TOOL_NOT_ALLOWED,
      message: `工具 ${tool.name} 未授权`,
      statusCode: 403,
    });
  }

  // 3. 带超时执行
  const result = await Promise.race([
    tool.execute(validatedArgs, ctx),
    timeout(ctx.timeout ?? 30000).then(() => {
      throw new AppError({
        code: ErrorCode.TOOL_TIMEOUT,
        message: '工具执行超时',
        statusCode: 504,
        retryable: true,
      });
    }),
  ]);

  // 4. 审计日志
  auditLog.record({ tool: tool.name, args: validatedArgs, result });

  return result;
}
```

**代码执行类工具的特殊要求**：

- 必须在隔离的 Docker 容器或 VM 中执行。
- 限制网络访问（默认禁用，需显式授权）。
- 限制文件系统访问（只读挂载 + 临时目录）。
- 限制执行时间与资源。

### 10.5 安全清单

提交 PR 前，请对照以下安全清单自查：

| 检查项 | 要求 |
|--------|------|
| 输入校验 | 所有外部输入经过 Schema 校验 |
| SQL 注入 | 使用参数化查询，禁止字符串拼接 SQL |
| 命令注入 | 使用 `execFile` 而非 `exec`，禁止拼接用户输入到命令 |
| XSS | 输出到前端的数据经过转义 |
| CSRF | 状态变更接口校验 CSRF Token 或使用 SameSite Cookie |
| 路径穿越 | 文件操作校验路径不包含 `..`，使用白名单目录 |
| SSRF | 外部 URL 请求校验目标地址，禁止访问内网 |
| 密钥泄露 | 密钥不在代码、日志、错误信息中明文出现 |
| 权限检查 | 每个 API 检查用户是否有权操作目标资源 |
| 速率限制 | 高风险操作（登录、工具执行）有频率限制 |
| 敏感数据 | 日志中不记录密码、Token、身份证等敏感信息 |
| 错误信息 | 错误响应不泄露系统内部信息（如堆栈、文件路径） |

```typescript
// ✅ 安全的错误响应（不泄露内部信息）
throw new AppError({
  code: ErrorCode.INTERNAL,
  message: '系统内部错误',  // 通用信息，不暴露细节
  statusCode: 500,
});
// 详细错误记录在服务端日志中，不返回给客户端

// ❌ 危险的错误响应
throw new Error(`Database connection failed: ${dbError.stack}`);
// 堆栈信息泄露给客户端，暴露内部结构
```
