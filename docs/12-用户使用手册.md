## 1. MyOpenClaw 简介

### 1.1 什么是 MyOpenClaw

MyOpenClaw 是一个**本地优先、自托管的开源 AI Agent 框架**。它可以帮助你将 AI 智能体接入各种聊天渠道（如 Telegram、Discord、飞书、WebUI 等），让 AI 助手在多个平台上为你服务。

简单来说，MyOpenClaw 就像是一个"AI 管家"：

- 你可以将它连接到你常用的聊天工具上
- 它能理解你的自然语言指令
- 它能调用各种工具和技能来帮你完成任务
- 它会记住你之前说过的话，实现连贯的多轮对话

MyOpenClaw 采用 MIT 开源协议，你可以自由使用、修改和分发。你的所有数据都存储在你自己的服务器上，不会发送给第三方。

### 1.2 核心特性

| 特性 | 说明 |
|------|------|
| 多渠道接入 | 支持 Telegram、Discord、飞书、微信、WebUI、CLI 等 20+ 渠道 |
| 自主循环 | 内置 Lobster 循环（感知 → 思考 → 规划 → 执行 → 观察 → 反思），实现自主任务完成 |
| 多模型支持 | 支持 OpenAI（GPT 系列）、Claude、DeepSeek 以及本地开源模型 |
| 记忆系统 | 支持短期会话记忆和长期向量记忆，实现上下文关联 |
| 技能扩展 | 内置丰富技能，支持自定义技能插件 |
| 定时任务 | 支持 Cron 定时任务，实现自动化工作流 |
| 本地优先 | 数据完全自托管，隐私可控 |
| 开源免费 | MIT 协议，无商业限制 |

### 1.3 支持的渠道

MyOpenClaw 目前支持以下渠道（持续扩展中）：

| 渠道 | 类型 | 说明 | 状态 |
|------|------|------|------|
| WebUI | Web 界面 | 浏览器直接访问的聊天界面 | 已支持 |
| CLI | 命令行 | 终端命令行交互 | 已支持 |
| Telegram | 即时通讯 | 通过 Telegram Bot 交互 | 已支持 |
| Discord | 即时通讯 | 通过 Discord Bot 交互 | 已支持 |
| 飞书 | 企业协作 | 通过飞书自建应用交互 | 已支持 |
| 微信 | 即时通讯 | 通过企业微信/公众号交互 | 已支持 |
| 钉钉 | 企业协作 | 通过钉钉机器人交互 | 开发中 |
| Slack | 企业协作 | 通过 Slack App 交互 | 已支持 |
| 企业微信 | 企业协作 | 通过企业微信应用交互 | 已支持 |
| Email | 邮件 | 通过邮件收发交互 | 已支持 |

### 1.4 适用场景

- **个人助手**：日程管理、信息查询、文件处理
- **团队协作**：代码审查、文档总结、会议纪要
- **知识管理**：知识库问答、文档检索、内容整理
- **自动化**：定时任务、流程自动化、数据监控
- **客服支持**：自动回复、工单处理、FAQ 问答

## 2. 首次使用准备

### 2.1 访问 WebUI

WebUI 是 MyOpenClaw 提供的浏览器聊天界面，是最简单的使用方式。

**访问步骤**：

1. 确认 MyOpenClaw 服务已启动并正常运行
2. 打开浏览器，在地址栏输入：
   ```
   http://你的服务器地址:18790
   ```
   如果在本机启动，直接访问 `http://localhost:18790`
3. 如果启用了鉴权，会显示登录页面，输入管理员设置的 Token 进行登录

**WebUI 界面说明**：

```
┌─────────────────────────────────────────────────────────┐
│  MyOpenClaw                              [设置] [关于]    │

│          │                                              │
```

### 2.2 CLI 客户端安装

CLI 客户端是 MyOpenClaw 提供的命令行交互工具，适合开发者和技术用户。

**安装方式**：

```bash
# 方式一：通过 npm 全局安装
npm install -g @myopenclaw/cli

# 方式二：通过 pnpm 安装
pnpm add -g @myopenclaw/cli

# 验证安装
myopenclaw --version
# 输出: MyOpenClaw CLI v1.0.0

# 查看帮助
myopenclaw --help
```

**首次连接**：

```bash
# 连接到本地 MyOpenClaw 服务
myopenclaw connect --host localhost --port 18780

# 如果启用了鉴权，需要提供 Token
myopenclaw connect --host localhost --port 18780 --token your-auth-token

# 连接成功后会进入交互模式
# ============================================
# MyOpenClaw CLI v1.0.0
# 已连接到 localhost:18780
# 输入消息开始对话，输入 /help 查看帮助
# ============================================
# (you) > 
```

### 2.3 首次配置向导

首次使用时，建议通过 WebUI 的配置向导完成基本设置。

**配置向导步骤**：

1. **欢迎页面**：点击"开始配置"进入向导
2. **选择 AI 模型**：
   - 选择你使用的 LLM 提供商（OpenAI / Claude / DeepSeek / 本地模型）
   - 输入对应的 API Key
   - 选择具体模型（如 GPT-4o、Claude 3.5 Sonnet 等）
   - 点击"测试连接"验证 API Key 是否有效

3. **配置渠道**（可选，可稍后配置）：
   - 选择需要启用的渠道（Telegram、Discord、飞书等）
   - 按向导提示输入各渠道的配置信息
   - 详见第 3 章"渠道配置指南"

4. **记忆设置**：
   - 选择记忆存储方式（默认使用内置 SQLite，无需额外配置）
   - 设置会话保留时间（默认 24 小时）
   - 设置历史消息保留条数（默认 50 条）

5. **完成配置**：
   - 确认配置信息
   - 点击"完成"保存配置
   - 系统自动重启相关服务使配置生效

## 3. 渠道配置指南

### 3.1 Telegram Bot 配置

#### 步骤一：在 Telegram 中创建 Bot

1. 打开 Telegram，搜索 `@BotFather`
2. 向 BotFather 发送 `/newbot` 命令
3. 按提示输入 Bot 的**显示名称**（如 `我的AI助手`）
4. 输入 Bot 的**用户名**（必须以 `bot` 结尾，如 `my_myopenclaw_bot`）
5. BotFather 会返回一个 **Bot Token**，格式类似：
   ```
   123456789:ABCdefGHIjklMNOpqrsTUVwxyz1234567890
   ```
6. **妥善保存此 Token**，后续配置需要使用

#### 步骤二：在 MyOpenClaw 中配置 Telegram 渠道

**方式一：通过 WebUI 配置**

1. 登录 WebUI，点击右上角"设置"
2. 选择"渠道管理" → "Telegram"
3. 填写配置：
   - Bot Token：粘贴从 BotFather 获取的 Token
   - 运行模式：选择 `轮询(Polling)` 或 `Webhook`
   - 如选择 Webhook 模式，填写 Webhook URL（需为 HTTPS 地址）
4. 点击"保存并启用"
5. 状态显示"已连接"表示配置成功

**方式二：通过配置文件**

```yaml
# config.yaml 中的 Telegram 渠道配置
channels:
  telegram:
    enabled: true                           # 启用 Telegram 渠道
    botToken: "123456789:ABCdef..."         # BotFather 提供的 Bot Token
    mode: polling                           # 运行模式: polling(轮询) 或 webhook
    # --- Webhook 模式配置（如果使用 webhook 模式）---
    webhookUrl: "https://your-domain.com/telegram/webhook"  # 回调地址
    webhookPort: 8443                       # Webhook 监听端口
    # --- 用户限制（可选）---
    allowedUsers:                           # 允许使用的用户 ID（为空则不限制）
      - 123456789                           # 你的 Telegram 用户 ID
```

#### 步骤三：验证连接

```bash
# 通过 API 验证 Telegram 渠道状态
curl -H "X-MyOpenClaw-Token: your-token" \
  http://localhost:18790/api/channels/status

# 预期返回:
# {
#   "telegram": {
#     "status": "connected",
#     "botName": "my_myopenclaw_bot",
#     "botUsername": "my_myopenclaw_bot"
#   }
# }
```

在 Telegram 中向你的 Bot 发送一条消息，如果收到 AI 的回复，说明配置成功。

#### 轮询模式与 Webhook 模式对比

| 对比项 | 轮询模式 (Polling) | Webhook 模式 |
|--------|-------------------|--------------|
| 配置难度 | 简单 | 较复杂（需 HTTPS） |
| 响应速度 | 稍慢（取决于轮询间隔） | 快（实时推送） |
| 网络要求 | 仅需出站访问 | 需公网 HTTPS 入站访问 |
| 适用场景 | 个人使用、本地部署 | 生产环境、高并发 |

### 3.2 Discord Bot 配置

#### 步骤一：创建 Discord Application

1. 访问 [Discord Developer Portal](https://discord.com/developers/applications)
2. 点击"New Application"，输入应用名称（如 `MyOpenClaw Bot`）
3. 创建完成后，进入应用设置页面

#### 步骤二：创建 Bot 并获取 Token

1. 在左侧菜单选择"Bot"
2. 点击"Add Bot"创建 Bot 用户
3. 在 Bot 页面，点击"Reset Token"获取 **Bot Token**
4. **妥善保存此 Token**

#### 步骤三：配置 Intents（权限）

在 Bot 页面的"Privileged Gateway Intents"部分，启用以下选项：

- **MESSAGE CONTENT INTENT**（必需，用于读取消息内容）
- **SERVER MEMBERS INTENT**（如需获取成员信息）
- **PRESENCE INTENT**（如需获取在线状态）

#### 步骤四：邀请 Bot 到服务器

1. 在左侧菜单选择"OAuth2" → "URL Generator"
2. 在"Scopes"中勾选 `bot`
3. 在"Bot Permissions"中勾选所需权限：
   - Send Messages（发送消息）
   - Read Message History（读取消息历史）
   - Attach Files（发送附件）
   - Embed Links（嵌入链接）
4. 复制生成的 URL，在浏览器中打开
5. 选择你的服务器，授权 Bot 加入

#### 步骤五：在 MyOpenClaw 中配置

```yaml
# config.yaml 中的 Discord 渠道配置
channels:
  discord:
    enabled: true                       # 启用 Discord 渠道
    botToken: "your-discord-bot-token"  # Discord Bot Token
    applicationId: "1234567890123456789"  # Application ID（从 General Information 页面获取）
    allowedGuilds:                      # 允许的服务器 ID（为空则不限制）
      - "9876543210987654321"
```

### 3.3 飞书应用配置

#### 步骤一：创建飞书自建应用

1. 访问 [飞书开放平台](https://open.feishu.cn/app)
2. 点击"创建企业自建应用"
3. 填写应用名称（如 `MyOpenClaw AI`）和描述
4. 创建完成后，进入应用详情页

#### 步骤二：获取凭证

在"凭证与基础信息"页面，记录以下信息：

- **App ID**：`cli_xxxxxxxxxxxx`
- **App Secret**：应用密钥

#### 步骤三：配置事件订阅

1. 在左侧菜单选择"事件订阅"
2. 设置请求地址（需为公网 HTTPS 地址）：
   ```
   https://your-domain.com/feishu/webhook
   ```
3. 添加订阅事件：
   - `im.message.receive_v1`（接收消息）
   - `im.message.reaction.created_v1`（消息反应，可选）

#### 步骤四：申请权限

在"权限管理"页面，申请以下权限：

| 权限名称 | 权限标识 | 用途 |
|---------|---------|------|
| 获取与发送单聊、群组消息 | `im:message` | 收发消息 |
| 获取用户基本信息 | `contact:user.base:readonly` | 获取用户信息 |
| 获取群组信息 | `im:chat:readonly` | 获取群组信息 |
| 上传/下载文件 | `im:resource` | 文件附件处理 |
| 获取与发送图片 | `im:image` | 图片消息处理 |

#### 步骤五：发布应用

1. 在"版本管理与发布"页面，创建新版本
2. 填写版本号和更新说明
3. 提交审核（企业管理员审核通过后生效）

#### 步骤六：在 MyOpenClaw 中配置

```yaml
# config.yaml 中的飞书渠道配置
channels:
  feishu:
    enabled: true                        # 启用飞书渠道
    appId: "cli_xxxxxxxxxxxx"            # 飞书 App ID
    appSecret: "your-app-secret"         # 飞书 App Secret
    verificationToken: "your-verify-token"  # 事件订阅验证 Token
    encryptKey: "your-encrypt-key"        # 事件订阅加密密钥（可选）
```

### 3.4 WebUI 使用

WebUI 是 MyOpenClaw 内置的 Web 聊天界面，无需额外配置即可使用。

**界面功能介绍**：

| 区域 | 功能说明 |
|------|---------|
| 左侧会话列表 | 显示所有对话会话，可新建、切换、删除会话 |
| 中间聊天区域 | 显示对话消息，支持文本、图片、文件展示 |
| 底部输入区 | 输入消息，支持附件上传、技能调用 |
| 右上角设置 | 渠道管理、模型配置、系统设置 |

**基本操作**：

1. **新建对话**：点击左侧"新对话"按钮，或使用快捷键 `Ctrl+N`
2. **发送消息**：在底部输入框输入文本，按 `Enter` 发送，`Shift+Enter` 换行
3. **上传文件**：点击输入框旁的"附件"按钮，或直接拖拽文件到聊天区域
4. **切换会话**：在左侧列表中点击不同会话
5. **删除会话**：右键点击会话，选择"删除"

## 4. 与 AI 助手对话

### 4.1 发送文本消息

与 MyOpenClaw AI 助手对话非常简单，就像与人类聊天一样：

**在 WebUI 中**：
1. 在底部输入框中输入你的消息
2. 按 `Enter` 键发送
3. AI 助手会在聊天区域显示回复

**在 CLI 中**：
```bash
(you) > 帮我写一首关于秋天的诗
```

**在 Telegram/Discord 中**：
直接向 Bot 发送消息即可。

**消息示例**：

```
我: 今天天气怎么样？

AI: 我无法直接获取天气信息，但我可以帮你做以下事情：
1. 如果你告诉我你所在的城市，我可以尝试帮你查询天气
2. 你也可以直接使用天气应用查询

请问你需要在哪方面的帮助呢？
```

### 4.2 发送文件附件

MyOpenClaw 支持处理用户发送的文件附件，包括文档、图片、代码等。

**支持的文件类型**：

| 类型 | 格式 | 说明 |
|------|------|------|
| 文档 | PDF、Word、TXT、Markdown | 可提取文本内容进行总结、分析 |
| 图片 | PNG、JPG、JPEG、GIF、WebP | 可进行图像识别和描述 |
| 代码 | 各种编程语言文件 | 可进行代码审查、解释、优化 |
| 数据 | CSV、JSON、Excel | 可进行数据分析、可视化 |
| 压缩包 | ZIP、TAR | 可解压并处理内部文件 |

**发送文件方式**：

- **WebUI**：点击"附件"按钮或拖拽文件到聊天区域
- **CLI**：使用 `/file` 命令
  ```bash
  (you) > /file report.pdf 帮我总结这份报告的核心内容
  ```
- **Telegram/Discord**：直接发送文件给 Bot

**使用示例**：

```
我: [上传 report.pdf] 帮我总结这份报告的核心内容

AI: 我已阅读了这份报告，以下是核心内容总结：

**报告主题**：2026 年第三季度销售业绩分析

**关键数据**：
- 季度总销售额：1,250 万元，同比增长 15%
- 新增客户：320 家，环比增长 22%
- 平均客单价：3,900 元

**主要发现**：
```

## 6. 定时任务配置

### 6.1 Cron 表达式说明

MyOpenClaw 使用标准的 5 段式 Cron 表达式来定义定时任务的执行时间。

```
┌──── 分钟 (0-59)
│ ┌──── 小时 (0-23)
│ │ ┌──── 日 (1-31)
│ │ │ ┌──── 月 (1-12)
│ │ │ │ ┌──── 星期 (0-7, 0和7都表示周日)
│ │ │ │ │
* * * * *  命令
```

**特殊字符说明**：

| 字符 | 含义 | 示例 | 说明 |
|------|------|------|------|
| `*` | 任意值 | `* * * * *` | 每分钟执行 |
| `,` | 列举值 | `0,30 * * * *` | 每小时的第 0 和 30 分钟 |
| `-` | 范围 | `0 9-18 * * *` | 每天 9 点到 18 点，每小时执行 |
| `/` | 步长 | `*/15 * * * *` | 每 15 分钟执行一次 |

**常用 Cron 表达式示例**：

| 表达式 | 说明 |
|--------|------|
| `0 9 * * *` | 每天 9:00 执行 |
| `0 9 * * 1-5` | 周一至周五 9:00 执行 |
| `0 */2 * * *` | 每 2 小时执行一次 |
| `*/30 * * * *` | 每 30 分钟执行一次 |
| `0 0 * * 0` | 每周日 0:00 执行 |
| `0 0 1 * *` | 每月 1 号 0:00 执行 |
| `0 9,12,18 * * *` | 每天 9:00、12:00、18:00 执行 |
| `0 0 1 1 *` | 每年 1 月 1 日 0:00 执行 |

### 6.2 创建定时任务

**通过 WebUI 创建**：

1. 点击左侧菜单的"定时任务"
2. 点击"新建任务"
3. 填写任务信息：
   - 任务名称：每天工作汇报提醒
   - Cron 表达式：`0 18 * * 1-5`（工作日 18:00）
   - 执行内容：请帮我生成今天的工作总结，并列出明天的重要事项
   - 渠道：选择执行渠道（如 Telegram）
4. 点击"保存"

**通过 CLI 创建**：

```bash
# 创建定时任务
(you) > /cron create --name "每日工作提醒" --schedule "0 18 * * 1-5" --message "请提醒我整理今天的工作总结"

# 输出:
# 定时任务已创建
# 任务 ID: cron-001
# 任务名称: 每日工作提醒
# 执行时间: 周一至周五 18:00
# 执行内容: 请提醒我整理今天的工作总结
# 下次执行: 2026-07-21 18:00:00
```

**通过 API 创建**：

```bash
curl -X POST http://localhost:18790/api/cron \
  -H "X-MyOpenClaw-Token: your-token" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "每周周报生成",
    "schedule": "0 17 * * 5",
    "message": "请根据本周的工作记录生成一份周报，包括完成事项、进行中事项和下周计划",
    "channel": "webui"
  }'
```

## 8. 多渠道同时使用

### 8.1 绑定多渠道

MyOpenClaw 支持将多个渠道绑定到同一用户身份，实现跨平台无缝对话。

**绑定方式**：

```bash
# 在 WebUI 中绑定
1. 登录 WebUI
2. 点击"设置" → "账号绑定"
3. 选择要绑定的渠道（Telegram、Discord、飞书等）
4. 按提示完成绑定验证

# 在 CLI 中绑定
(you) > /bind telegram
# 输出: 请在 Telegram 中向 Bot 发送以下验证码: BIND-8X9K2M
# 在 Telegram 中发送验证码完成绑定

(you) > /bind discord
# 输出: 请在 Discord 中向 Bot 发送以下验证码: BIND-P3Q7R1
```

**绑定后效果**：
- 在任意渠道发送的消息，AI 都能记住之前的对话
- 从 Telegram 切换到 Discord 继续对话，AI 不会"失忆"
- 定时任务可以在任意绑定渠道中推送

### 8.2 会话隔离说明

虽然多渠道共享用户身份，但每个渠道的会话默认是**隔离**的，这意味着：

| 隔离维度 | 说明 |
|---------|------|
| 会话上下文 | 每个渠道有独立的会话上下文，不自动同步 |
| 长期记忆 | 跨渠道共享，AI 能通过向量记忆关联历史信息 |
| 定时任务 | 默认在创建时的渠道推送，可配置跨渠道推送 |

**会话隔离配置**：

```yaml
# config.yaml 中的会话隔离配置
channels:
  sessionMode: isolated    # isolated: 渠道隔离  | shared: 跨渠道共享上下文
```

```bash
# 手动切换会话上下文到另一个渠道
(you) > /session switch --from telegram --to discord
```

## 9. 常见问题 FAQ

### Q1: MyOpenClaw 是免费的吗？

**A**: MyOpenClaw 本身是开源免费的，采用 MIT 协议。但使用 MyOpenClaw 调用的 AI 大模型（如 OpenAI GPT-4、Claude 等）可能会产生 API 调用费用，具体费用取决于你选择的模型提供商和用量。你也可以使用本地开源模型（如通过 Ollama 部署）来避免 API 费用。

### Q2: 我的数据安全吗？会被上传到第三方吗？

**A**: MyOpenClaw 采用本地优先架构，你的所有对话数据、记忆数据都存储在你自己的服务器上。只有在调用 LLM API 时，对话内容会发送给你配置的模型提供商（如 OpenAI）。如果你使用本地模型，则数据完全不会离开你的服务器。

### Q3: 支持哪些 AI 大模型？

**A**: MyOpenClaw 支持以下模型：
- **OpenAI**：GPT-4o、GPT-4 Turbo、GPT-3.5 Turbo 等
- **Claude**：Claude 3.5 Sonnet、Claude 3 Opus 等
- **DeepSeek**：DeepSeek Chat、DeepSeek Coder 等
- **本地模型**：通过 Ollama 运行的 Llama、Qwen、Mistral 等开源模型

### Q4: AI 助手回复很慢怎么办？

**A**: 回复速度受以下因素影响：
1. **模型选择**：GPT-4o 比 GPT-3.5 慢，可切换为更快的模型
2. **网络延迟**：检查与 LLM API 的网络连通性
3. **对话长度**：过长的对话历史会增加处理时间，可使用 `/clear` 清除上下文
4. **服务器性能**：检查服务器 CPU/内存使用情况

### Q5: 如何更换 AI 模型？

**A**: 可以通过以下方式切换模型：
- **WebUI**：设置 → AI 模型 → 选择新模型
- **CLI**：输入 `/model <模型名称>`
- **配置文件**：修改 `config.yaml` 中的 `llm.model` 字段

### Q6: AI 忘记了之前说的话怎么办？

**A**: 这可能是上下文过长导致早期消息被截断。解决方法：
1. 使用 `/context` 查看当前上下文使用情况
2. 使用 `/context summary` 手动触发摘要
3. 开始新会话（`/session new`），AI 会通过长期记忆关联之前的信息
4. 调整 `memory.session.maxHistory` 配置增加保留的历史消息数

### Q7: 如何限制只有我能使用 Bot？

**A**: 在配置文件中设置 `allowedUsers`：
```yaml
channels:
  telegram:
    allowedUsers:
      - 123456789   # 你的 Telegram 用户 ID
```
设置后，只有列表中的用户才能与 Bot 交互。

### Q8: Bot 在 Telegram 中不回复消息怎么办？

**A**: 排查步骤：
1. 检查 Bot Token 是否正确
2. 通过 API 检查渠道状态：`curl http://localhost:18790/api/channels/status`
3. 检查服务器是否能访问 `api.telegram.org`
4. 查看 MyOpenClaw 日志是否有错误信息
5. 如果使用 Webhook 模式，确认回调地址可公网访问且为 HTTPS

### Q9: 支持发送图片吗？

**A**: 支持。你可以直接向 Bot 发送图片，AI 助手可以识别图片内容并进行描述、分析。也支持发送文件附件（PDF、Word、代码文件等）。

### Q10: 如何自定义技能？

**A**: MyOpenClaw 支持自定义技能插件。将技能文件放在 `data/skills/` 目录下，系统会自动加载。技能开发请参考开发者文档。也可以通过 WebUI 的技能管理界面上传自定义技能。

### Q11: 定时任务没有执行怎么办？

**A**: 排查步骤：
1. 使用 `/cron list` 查看任务状态是否为"启用"
2. 检查 Cron 表达式是否正确
3. 查看 MyOpenClaw 日志中是否有执行记录
4. 确认任务执行时对应的渠道是否在线

### Q12: 可以同时在多个群组中使用吗？

**A**: 可以。MyOpenClaw 支持在多个群组/频道中同时运行。每个群组的会话默认是隔离的，互不影响。可以在配置中设置 `allowedGuilds`（Discord）来限制 Bot 只在指定服务器中响应。

### Q13: 如何导出对话记录？

**A**: 使用以下命令导出：
```bash
# 导出单个会话
(you) > /sessions export sess_001 --format markdown

# 导出所有会话
(you) > /sessions export --all --format json --output /path/to/export/
```

### Q14: 对话内容会被用来训练模型吗？

**A**: MyOpenClaw 本身不会使用你的对话数据训练任何模型。但如果你使用第三方 LLM API（如 OpenAI），请查阅对应提供商的数据使用政策。通常商业 API 提供商提供"不用于训练"的选项，建议在 API 提供商的后台设置中关闭数据用于训练的选项。

### Q15: 如何查看 API Token 消耗量？

**A**: 可以通过以下方式查看：
- **WebUI**：设置 → 使用统计，查看 Token 消耗趋势
- **CLI**：输入 `/stats` 查看使用统计
- **API**：`curl http://localhost:18790/api/stats/tokens`
- **Prometheus 指标**：`curl http://localhost:18791/metrics | grep tokens`

### Q16: 支持语音消息吗？

**A**: 当前版本暂不支持语音消息输入。这是一个计划中的功能，将在后续版本中推出。目前你可以先将语音转为文字，再发送给 AI 助手。

### Q17: 如何更新到最新版本？

**A**: 更新方式取决于部署方式：
- **源码部署**：`git pull && pnpm install && pnpm build && pnpm start`
- **npm 方式**：`npm update -g myopenclaw`
- 详细升级步骤请参考《16-变更记录.md》第 4 章"升级指南"
